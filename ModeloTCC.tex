\begin{resumo}
A organização de amostras e análises laboratoriais do NAPI Abelhas motivou a proposta de uma plataforma web apresentada no TCC 1. Este trabalho descreve a implementação dessa proposta e confronta os requisitos planejados com as funcionalidades identificadas no software desenvolvido. A solução é composta por uma interface em Next.js e uma API em NestJS, com autenticação pelo Clerk, persistência em PostgreSQL por meio do Prisma e armazenamento de arquivos em MinIO mediante URLs assinadas. O modelo permite registrar produtores, pontos de coleta, espécies de abelhas, tipos de amostra, amostras, análises e arquivos associados. O desenvolvimento também introduziu organizações e papéis de acesso, além de um ambiente de infraestrutura descrito em Docker Compose. A avaliação apresentada é técnica e documental, baseada na inspeção dos projetos e nas verificações executáveis no ambiente de desenvolvimento. A comparação evidencia funcionalidades implementadas e limitações ainda existentes, como a ausência de filtros avançados na API e de comprovação de uma estratégia de cache com Redis. Não foi realizada avaliação de uso com pesquisadores do NAPI Abelhas.
\end{resumo}

\begin{abstract}
The organization of laboratory samples and analyses at NAPI Abelhas motivated the web platform proposed in TCC 1. This work describes the implementation of that proposal and compares the planned requirements with the features identified in the developed software. The solution comprises a Next.js interface and a NestJS API, with authentication provided by Clerk, PostgreSQL persistence through Prisma, and file storage in MinIO using signed URLs. The data model supports producers, collection sites, bee species, sample types, samples, analyses, and associated files. Development also introduced organizations and access roles, as well as infrastructure defined with Docker Compose. The assessment is technical and documentary, based on inspection of the projects and checks that can be performed in the development environment. The comparison identifies implemented features and remaining limitations, including the absence of advanced API filters and of evidence for a Redis caching strategy. No user evaluation with NAPI Abelhas researchers was conducted.
\end{abstract}
